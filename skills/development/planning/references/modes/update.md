# 업데이트

기존 아키텍처에 기능을 추가하거나 수정하는 계획을 세운다. 기존 구조에 담긴 설계 의도를 지키는 것이 우선이다.

## 필수 입력

- 업데이트 내용

기존 코드는 직접 읽어서 파악한다. 문서를 따로 요청하지 않는다.

## 단계

1. **기존 구조 파악**
   - 업데이트와 관련된 모듈, config가 흘러가는 경로, 디렉토리 간 의존 방향, 기능을 끼울 기존 위치
2. **변경 계획**
   - 수정할 곳, 추가할 곳, 변경으로 필요 없어지는 코드
   - 기존 구조 안에서 해결하는 것이 기본이다. 구조를 깨야만 한다면 이유와 대안을 제안하고 사람이 정한다

## 산출 문서

- `docs/planning-output.md`: 파악한 기존 구조, 변경 계획
- `docs/task/01_XXXX.md`: 작업 계획서 1개. 규모가 커서 나눠야 하면 나눌지 먼저 묻는다

## 점검

- config 흐름을 우회하는 값(모듈 내부 하드코딩 등)이 계획에 없는가
- 기존 의존 방향을 어기지 않는가
- 필요 없어지는 코드를 빠뜨리지 않았는가
