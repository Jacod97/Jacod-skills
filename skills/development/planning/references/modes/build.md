# 빌드

리서치로 검증된 연구 코드를 시스템으로 만드는 구조를 계획한다. 새로 만드는 것이 아니라, 난잡한 연구 스크립트에 구조를 잡는 일이다.

## 필수 입력

- 연구 코드 디렉토리
- `DLFA.md`
- 연구 계획서

## 단계

1. **문제와 규모**
   - 이 시스템이 해결할 문제, 예상 규모(사용자, 데이터 양, 확장 계획)를 확인한다
2. **연구 코드 파악**
   - `DLFA.md`의 결론(검증됨·버림)과 시도 표를 먼저 읽는다. 실패한 시도를 계획에 다시 넣지 않는다
   - 검증된 기능, 실험하며 실제로 자주 바뀌던 부분(확장이 필요한 곳의 후보)을 정리해 확인받는다
3. **구조 설계**
   - 디렉토리 구조, 디자인 패턴을 제안한다. 규모에 맞게, 과하지 않게
   - 사람이 구조를 제안하면 그것을 기준으로 장단점을 짚고 합의한다
4. **API 명세**
   - 모듈 간 인터페이스를 정한다
5. **작업 계획**
   - 구현 순서를 정하고 task로 나눈다

## 산출 문서

- `docs/planning-output.md`: 양식 `assets/planning-output-build.md` (디렉토리 구조, 의존 관계·데이터 흐름 다이어그램, 디자인 패턴, API, 산출 파일)
- `docs/task/01_XXXX.md`, `02_XXXX.md`, ...: 양식 `assets/task.md`

## 점검

- 연구 코드의 검증된 기능이 구조에서 빠지지 않았는가
- 규모에 비해 과한 구조가 아닌가
- 자주 바뀌던 부분이 바꾸기 쉬운 위치에 있는가
- 데이터 흐름의 각 단계 형태가 API의 Input/Output과 맞는가
- 의존 관계에 역방향 화살표가 없는가
