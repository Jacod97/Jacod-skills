# core: 모든 다이어그램

원칙: 글은 이름만 맡고, 관계는 색·모양·위치·선 종류가 맡는다.

## 텍스트

- 박스 라벨은 명사 1~3단어 또는 기호. 동사구·문장 금지
  - 나쁨: `Determine Current Region`, `Query VLM for Stopping Condition`
  - 좋음: `Region Estimation`, `Stop Check`, `Cross-Attention`, `E`
- 색·위치·선 종류로 이미 나타낸 정보는 글로 반복하지 않음. 같은 이름은 그림에 한 번만
  - 예: 패널 제목이 `Global Exploration`이면 그 패널로 들어가는 화살표에 같은 라벨을 달지 않음
  - 예: 점선 색으로 출처를 알 수 있으면 점선에 출처 이름을 달지 않음
- 그림 전체 제목 금지. 캡션이 맡음. 패널·단계 이름(`Decoder Block`, `I. Pretrain`)은 허용
- 데이터 이름은 처음 나올 때만 붙이고, 이후에는 기호나 그림만
- 수식 기호는 본문과 같은 기호·같은 글꼴
- 정의, 수식형 설명(`Region(s) = [r1, r2, ..]`), 예시 문장은 본문이나 캡션으로

## 시각 부호화

- 색 = 종류
  - 한 그림 안에서 같은 색은 같은 뜻. 같은 문서의 여러 그림에서도 가능하면 유지
  - 연한 채움색 4~5개 이내. 팔레트는 `assets/palette.md`
  - frozen·비활성은 회색
- 모양 = 역할
  - 모듈: 채운 둥근 사각형, 테두리 없음
  - 데이터: 내용물 그림, 또는 흰 바탕에 얇은 테두리 박스
  - 스칼라·변수: 원 또는 칩
- 데이터는 가능하면 내용물 그림(스켈레톤, 이미지, 파형, 지도)으로
- 선 종류마다 뜻 하나, 그림 안에서 고정
  - 기본: 실선 = 흐름, 점선 = 생략·확대·참조
- 글리프는 보면 바로 아는 기호만: `+`, `×`, `⊙`, concat(`‖`), `~`(sinusoidal) 정도
  - 임의로 뜻을 정한 기호(삼각형 = Add+Norm+MLP 등) 금지
  - 범례 만들지 않음. 칩·기호의 뜻은 캡션이나 본문에서 정의

## 배치

- 흐름 방향은 그림 전체에서 하나
- 화살표는 직각으로 꺾음. 화살촉 한 종류, 선 굵기 한 종류. 교차 최소화
- 같은 종류 박스는 크기·정렬을 맞춤
- 같은 대상이 반복되면 같은 순서·같은 위치 (예: 매 호출의 입력 3개)
- 한 패널 = 한 type. 섞이면 패널로 나누고 확대선(얇은 회색 점선)으로 연결
- 요소는 최대한 적게 묶음. 개수 상한은 두지 않음. 개수를 맞추느라 균형을 깨지 않음
- 여백을 넉넉히. 컨테이너 안쪽 여백과 박스 사이 간격을 일정하게

## 캡션

- 캡션 초안을 함께 전달함
- 첫 문장: 그림이 무엇을 보여주는지
- 이어서 그림 속 기호·칩·색의 뜻 정의 (범례 대신)

## 점검

- 렌더링 결과를 직접 봄
- 단어 수 셈: 3단어 넘는 라벨, 문장, 두 번 나온 단어가 있으면 고침
- 화살표마다 뜻을 한 마디로 말할 수 있는지. 말할 수 없으면 지움
- 지우거나 합쳐도 뜻이 남는 박스가 있는지
- 색 하나에 뜻이 둘 이상 붙지 않았는지
- 글자 겹침, 화살표가 박스를 관통하는 곳이 없는지
- 그림 속 기호가 캡션이나 본문에 모두 정의됐는지
