# 모듈: README 그림

## 규칙

- 사용자가 적합한 다이어그램, 아키텍처 이미지, 작업 흐름 그림 등을 제공했다면 **해당 에셋을 우선 사용한다**. 별도 요청 없이 다시 그리거나 교체하지 않는다. 관련성과 가독성을 확인하고 적절한 위치에 유효한 경로로 연결한다.
- 적합한 제공 이미지가 없고 **그림이 이해를 실질적으로 돕는 경우**, 별도로 설치된 **`writing/draw-diagram`** 스킬로 아키텍처·작업 흐름·데이터 흐름 그림을 만든다. 해당 스킬의 규칙과 출력 형식을 따르고, 검증된 구성 정보와 대상 독자·상세 수준만 전달한다.
- 그림을 채우려고 아키텍처를 지어내지 않는다. `writing/draw-diagram`을 사용할 수 없으면 한계를 밝히고 스킬이나 이미지를 요청한다. 생성하지 않은 그림이 있다고 주장하지 않으며, 가능한 부분은 정확한 텍스트 설명으로 진행한다.
- 장식만을 위해 그림을 추가하지 않는다. 코드가 복잡하다는 사실만으로 README에 아키텍처 그림이 필요한 것은 아니다.
- 새로 작성하는 그림의 설명, 캡션과 대체 텍스트는 영어로 쓴다. 제공 에셋의 보존 원칙은 유지한다.

## 점검

- 제공 에셋이 보존되었고 이미지 경로가 유효한지 확인한다.
- 그림 내용이 근거와 일치하고 README에서 읽기 쉬운지 확인한다.
- 생성한 소스와 렌더링 결과가 실제로 존재하는지 확인한 뒤 연결한다.
