# 유형: 애플리케이션·서비스

## 속성

- 대상: 웹 애플리케이션, 백엔드 서비스, 에이전트 시스템, 데스크톱 애플리케이션.
- 독자 요구: 프로그램으로 수행할 수 있는 작업과 사용·운영 방법 파악.

## 모듈

- 이미지가 제공되었거나 그림이 이해를 돕는 경우: `../modules/figures.md`.

## 권장 구성

1. 개요: 사용자의 문제, 프로젝트의 역할과 이점.
2. 기능: 모듈 목록 대신 실제 수행 가능한 작업.
3. 시작하기: 확인된 사전 조건, 설치, 시작과 접속 방법.
4. 사용법: 주요 사용자 작업 흐름과 결과.
5. 설정: 운영자가 지정할 값. 필수와 선택 설정 구분.
6. 아키텍처 또는 배포: 대상 독자에게 필요한 경우에만 포함.

## 규칙

- 내부 서비스 간 호출 대신 사용자·운영자 관점에서 작업 흐름을 설명한다.
- UI가 있으면 제공된 스크린샷과 짧은 사용 예제를 우선한다.
- 개발 환경과 운영 환경의 요구 사항이 실제로 다르면 구분한다.
- 아키텍처는 주요 외부 구성 요소, 역할과 데이터 흐름만 설명한다.
- 내부 클래스, 라우트 처리기 또는 디렉터리를 기능으로 나열하지 않는다.

## 점검

- 설치, 시작과 설정이 지원 환경에 맞는지 확인한다.
- 기능과 흐름이 내부 구성 요소가 아닌 사용자·운영자의 작업을 설명하는지 확인한다.
