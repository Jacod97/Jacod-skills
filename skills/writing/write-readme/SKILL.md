# README 작성 (write-readme)

이 파일은 길잡이다. 규칙 본문은 `references/` 아래에 계층별로 나뉘어 있고, 지금 쓰는 README에 필요한 파일만 읽는다.

## 계층과 우선순위

```
references/core.md              0층  모든 README
references/types/<type>.md      1층  저장소 종류
references/modules/<module>.md  가로축  type과 작업에 필요한 기능
```

- 읽는 순서: core → type → 모듈
- 같은 항목에서 규칙이 부딪치면 type이 core를 구체화한다. 사실 검증과 작업 범위 제한은 모든 type에 적용한다.
- 모듈은 type의 "모듈" 항목에 적힌 조건에 해당할 때만 읽는다.

## 1. 분류

| type | 요청 대상 | 읽을 파일 |
|---|---|---|
| 애플리케이션·서비스 | 웹·데스크톱 앱, 백엔드, 에이전트 시스템 | `references/types/application.md` |
| 라이브러리·SDK·CLI | 패키지, 재사용 모듈, 명령줄 도구 | `references/types/library.md` |
| 연구·실험 | 논문 구현, 모델 학습, 시뮬레이션, 실험 저장소 | `references/types/research.md` |
| 자료·스킬 모음 | 스킬, 템플릿, 참고 자료, 에셋 모음 | `references/types/collection.md` |

- 대상 독자, 목적, 사용 방식과 필수 항목을 확인한다. README 결과물은 대화 언어나 저장소의 기존 언어와 관계없이 항상 영어로 작성한다. 스킬 지침 자체는 한국어로 유지한다.
- 저장소의 사용자 관점 목적과 공개 인터페이스로 주 type을 정한다. 판단이 README 내용을 실질적으로 바꿀 때만 묻는다.
- 혼합형이면 보조 type에서 필요한 규칙만 추가한다. 모든 type의 목차를 합치지 않는다.

## 2. 규칙 로드

1. `references/core.md`를 끝까지 읽는다.
2. 분류한 type 파일을 읽는다.
3. type의 "모듈" 항목에서 현재 작업에 필요한 모듈만 읽는다.

## 3. 절차

1. 분류와 규칙 로드.
2. 자료 수집: 사용자가 제공한 설명, 문서, 이미지, 예제를 먼저 확인한다. 소스는 공개 동작과 명령을 검증하는 데 필요한 진입점, 매니페스트, 도움말, 설정, 예제만 읽는다.
3. 구성: type의 권장 순서를 바탕으로 프로젝트 목적과 실용적 가치를 먼저 설명하고, 독자가 이해·선택·설치·실행·설정·사용하는 데 필요한 항목만 남긴다.
4. 그림 처리: 적합한 제공 이미지가 있거나 그림이 이해를 돕는 경우 `references/modules/figures.md`를 적용한다.
5. 작성: 영어로 된 GitHub-flavored Markdown으로 `README.md`를 작성하거나 수정한다. 제목과 본문은 객관적인 문서체를 사용하고, 독자에게 말을 걸거나 질문하는 대화체는 쓰지 않는다. 정확한 기존 정보, 사용자 에셋, 정상 링크를 보존하고 관련 없는 파일을 덮어쓰지 않는다.
6. 검증: core 점검 + type 점검 + 사용한 모듈의 점검. 명령, 경로, 이미지, 탐색 링크, 영어 작성 여부, 대화체·질문형 제목의 부재와 불필요한 내부 구현 설명을 확인한다.
7. 전달: 결과 파일과 확인하지 못한 사실을 알린다. 중요한 정보가 빠졌으면 질문하고, 명령이나 결과를 지어내지 않는다.

## 새 type·모듈 추가

- 새 저장소 종류는 `references/types/`에 파일 하나로 추가하고, 1절 표에 한 줄을 더한다. type 파일은 속성 + 모듈 + 권장 구성 + 고유 규칙 + 점검으로 구성한다.
- 둘 이상의 type이 공유하는 규칙은 core나 모듈로 올린다.
- 새 기능은 `references/modules/`에 추가하고, 필요한 type에 사용 조건을 적는다.
