# type: 리뷰 (설명 문서)

논문, 기술 개념, 학습 개념을 빈자리 없이 설명하는 문서를 만든다.

LLM은 많이 알기 때문에 설명 중간에 단계를 건너뛰어도 스스로는 끊긴 줄 모른다. 이 type의 목적은 독자가 실제로 모르는 지점에서 설명이 끊기지 않게 하는 것이다.

## 속성
- 읽는 방식: 선형
- 출력: 수식이 많으면 LaTeX 기본 서식으로 PDF. 수식이 거의 없으면 채팅 답변이나 문서 아티팩트.
- 합의: 서술형 진단 → 독자 프로필 → core 구성안 협의
- 독자: 요청한 사람 본인. 묻지 않는다. 사용자가 다른 사람을 위한 문서라고 말한 경우에만 그 사람 기준으로 진단 답을 받는다.
- 모듈: `modules/source-ingest.md`, `modules/latex.md`, `modules/figures.md`, `modules/reader-review.md`, `modules/bibliography.md`(인용이 있을 때)
- 진술의 지위: 설명이 목적이므로 "왜"를 쓴다. 단, 논문의 주장과 작성자의 해설은 구분한다.
- 정의 범위: 독자 프로필에서 "부분적으로 아는 개념"과 "모르는 개념"은 반드시 설명한다.

## 절차
1. 원자료 수집
2. 선행 개념 목록
3. 서술형 진단
4. 독자 프로필 작성
5. 구성안 협의 (core): 프로필을 반영한 구성안을 제안하고 승인받음
6. 작성
7. 독자 검토 모듈 실행
8. 질문지를 사용자에게 보여주고 수정

## 진단을 하는 이유
1. 설명이 끊기는 자리를 미리 찾는다.
   - 예: 본문에 "이 데이터셋은 SMPL 관절 24개로 구성된다"라고 썼는데 독자가 SMPL을 모르면, 이 문장은 설명이 아니라 알아들을 수 없는 말이 된다. 진단은 이런 문장이 어디서 생길지를 쓰기 전에 찾는 일이다.
   - 진단 결과는 등급이 아니라 "이 독자는 문서의 이 단계에서 막힌다"는 위치 정보다.
2. 독자 검토 서브에이전트의 지식 수준을 정한다.
   - 독자 프로필이 그대로 서브에이전트에게 넘어가고, 서브에이전트는 프로필의 모르는 개념을 모르는 것처럼 읽는다. 진단이 틀리면 검토도 엉뚱한 곳을 짚는다.

## 선행 개념 목록
- 이 문서를 이해하려면 반드시 알아야 하는 개념을 뽑는다.
- 개념마다 두 가지를 적는다.
  - 문서의 어느 단계에서 쓰이는지 (예: "경사하강법 — 렌더링 손실로 MLP 가중치를 갱신하는 단계")
  - 모르면 그 단계에서 무엇을 못 따라오는지
- 개념끼리 무엇이 무엇의 기초인지 순서(선행 개념 사슬)를 정한다.

## 서술형 진단
- 자기평가를 묻지 않는다. "알고 있나요?", "완벽히 안다 / 직관만 안다 / 잘 모른다" 같은 선택지는 진단이 아니다.
- 객관식도 쓰지 않는다. 선택지는 찍어서 맞힐 수 있고, 보기 자체가 힌트가 된다.
- 문항은 그 개념이 문서에서 쓰이는 단계를 따라오는 데 실제로 필요한 능력을 확인하도록 만든다. 일반 텍스트로 묻고, 답도 텍스트로 받는다.
  - 예 (NeRF, 경사하강법이 쓰이는 단계: 렌더링 손실로 가중치 갱신): "가중치 $w$ 하나짜리 모델에서 손실 $L(w)$가 주어졌을 때, 경사하강법으로 $w$를 한 번 갱신하는 식을 쓰고 각 항이 무엇인지 설명해 줘."
  - 예 (푸리에 변환, 내적이 쓰이는 단계: 신호를 기저 함수로 분해): "벡터 $(3, 4)$를 기저 $(1,0), (0,1)$로 나타낼 때 각 계수를 어떻게 구하는지 설명해 줘. 기저가 직교가 아니면 무엇이 달라지는지도."
- 문항은 선행 개념 사슬의 아래쪽(기초)부터 낸다. 기초에서 막히면 그 위 개념 문항은 생략하고 모르는 것으로 둔다.
- 한 번에 2~3문항씩, 전체 3~8문항. "모르겠음"이라고 답해도 된다고 알린다.
- 채점은 에이전트가 답을 읽고 개념마다 판정한다: 앎 / 부분적으로 앎 / 모름. 판정마다 근거 한 줄 (예: "갱신 식은 맞지만 학습률의 역할을 설명하지 못함").

## 독자 프로필
```
[독자 프로필]
- 독자: (요청한 사람 본인 / 사용자가 지정한 다른 사람)
- 아는 개념: 설명 없이 써도 됨
- 부분적으로 아는 개념: 무엇이 빠졌는지 / 문서의 어느 단계에서 메울지
- 모르는 개념: 문서의 어느 단계에서 막히는지 / 그 단계 앞에서 처음부터 설명
- 진단하지 않았지만 모를 것으로 보이는 개념: (추정, 근거)
```
- 이 프로필이 구성안과 서브에이전트 검토의 기준이 된다.
- 범위는 에이전트가 정한다. 사용자는 모르기 때문에 설명을 요청한 것이므로 범위·깊이·다룰 개념을 사용자에게 정하라고 묻지 않는다. 목표 개념까지의 선행 개념 사슬과 프로필로 정한다.
- 구성안 협의 때 프로필을 함께 보여주고, 구성안의 각 절에 "이 절에서 메우는 빈자리"를 적는다.

## 작성 규칙 (core·선형 규칙보다 우선)
- 다른 부분을 가리킬 때 "3.1절", "그림 2" 같은 번호를 쓰지 않는다. 개념 이름을 직접 쓰고, 필요하면 그 식을 다시 적는다. 예: "앞에서 유도한 투과율 식 $T(t)=\exp(-\int\sigma\,ds)$를 쓰면"
- 기호표를 맨 앞에 따로 만들지 않는다. 앞에서 나온 기호라도 다시 쓰이면 그 자리에서 다시 설명한다.
- 모든 단계에 "왜 이렇게 하는가"를 적는다.
- 수식 유도는 독자가 따라올 수 있는 단계로 나눠 모두 보인다. 직관 설명만으로 끝내지 않는다.
- 가능하면 실제로 계산한 숫자 예시를 넣는다. 숫자와 유도한 식(기울기 등)은 코드로 계산해 검증한다.

## 질문지 반영
- 독자 검토 모듈에 위 프로필을 그대로 넘긴다.
- 서브에이전트의 질문지를 고치거나 줄이지 않고 그대로 보여준다.
- 질문마다 어떻게 고칠지 한 줄씩 붙인다.
- 사용자가 확인하면 고친다. "막힘" 질문이 많았으면 고친 뒤 같은 프로필로 한 번 더 검토한다.

## 점검
- [ ] 프로필의 모르는·부분적으로 아는 개념이 쓰이는 모든 단계 앞에 설명이 있음
- [ ] 번호 참조("3.1절", "그림 2") 없음
- [ ] 수치 예시와 유도를 코드로 검증함
- [ ] 독자 검토 질문지를 사용자에게 보여주고 반영함
