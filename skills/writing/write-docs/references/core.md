# core 규칙 (모든 문서)

모든 type에 적용한다. type 파일이 다르게 정한 항목은 type을 따른다.

## 구성안 협의 (모든 문서, 예외 없음)
- 문서를 쓰기 전에 에이전트가 구성안(장·절 목록)을 먼저 제안한다. 사용자에게 구성을 정해 달라고 하지 않는다.
- 구성안에는 장·절마다 다음을 적는다.
  - 무엇을 설명하는지
  - 왜 이 위치에 오는지: 앞 절에서 무엇을 받아 다음 절로 무엇을 넘기는지
- 구성안 끝에 전체 흐름을 한두 문장으로 적는다. 예: "데이터 구성 → 각 파일의 형태 → 전처리 과정 순서로, 앞 장의 필드 이름을 뒤 장에서 그대로 쓴다."
- 사용자는 읽고 승인하거나 다른 흐름을 제안한다. 제안을 받으면 반영한 구성안을 다시 보여주고, 승인될 때까지 반복한다.
- 승인 전에는 어떤 파일도 만들지 않는다. 작성 중 구성이 크게 바뀌어야 하면 멈추고 바뀐 구성안을 다시 제시한다.
- 여기서 구성안은 협의용이다. 문서 본문에 목차를 넣지 않는다는 규칙과는 별개다.
- type은 구성안 협의 앞이나 함께 할 단계(진단, 빠진 선택 확인 등)를 더할 수 있지만, 구성안 협의 자체를 빼지 않는다.

## 언어와 문체
- 출력 언어는 사용자 언어가 기본이다. 영어로 기본 설정하지 않는다.
- 서술 문장은 "~다"로 끝낸다. "~습니다"와 존댓말은 쓰지 않는다.
- 용어 표기(영어 원문, 한글 발음 표기 금지, 한영 혼합 명사, 원문 유지)와 개조식 종결은 `references/word-rule.md`를 참고한다.
- 소제목은 명사구로 쓴다. 질문형("무엇을 만드는 것인가"), 주장·서술형("출발점: DDIM은 Non-Markovian이다")은 쓰지 않는다.
  - 좋음: "DDIM의 Non-Markovian 구조", "변환 과정", "특이사항"
- 대화체, 감탄, 독자에게 말을 거는 표현을 쓰지 않는다.

## 내용
- 지어내지 않는다. 숫자·실험 결과는 원자료 값, 직접 계산한 값, 실제 실행 결과만 쓴다. 참고문헌, DOI, URL, 데이터셋, 소프트웨어 기능도 확인한 것만 쓴다. 없는 값을 보간하거나 만들지 않는다.
- 계산으로 얻은 값과 확인하지 못한 값은 따로 밝힌다. 본문에서는 "미확인"으로 쓰고, 전달 메시지에도 적는다.
- 출처를 밝힌다. 1차 출처(논문, 공식 저장소, 표준 문서, 실제 파일)를 우선한다. 코드로 확인한 사실은 확인한 위치를 적는다. 예: "raw_pose_processing.ipynb의 코드를 직접 확인한 것이다."
- 진술의 지위를 구분한다. 얼마나 엄격하게 구분할지는 type이 정한다.
- 형용사 평가 대신 숫자와 단위를 쓴다.
- 군더더기를 넣지 않는다.
  - 상투어 금지: 핵심 요약, 결론적으로, 흥미롭게도, 주목할 만한, 성공적으로, 효과적으로, ~것으로 보입니다
  - "이 문서를 읽는 방법" 같은 메타 안내 절 금지
  - 목차, 부제목, "한눈에 보기" 같은 요약 상자 금지 (type이 허용한 경우만 예외)
  - 분량을 채우는 절, 같은 설명 반복 금지. 모든 문단이 문서의 목적을 진전시켜야 함
- 학술 초록(abstract)은 요약 상자와 다르다. type이 허용할 때만 쓴다.
- 수식·그림·표·의사코드는 설명에 필요할 때만 넣는다.

## 용어·수식·표
- 정의 없이 처음 나오는 용어·약어·모델명·기호가 없어야 한다. 무엇을 정의할지는 type이 정한다.
- 기호는 처음 쓸 때 의미와 함께 shape, 단위, 좌표계, 정규화 방식을 필요한 만큼 정의한다.
- 수식 바로 아래에 기호 설명을 개조식으로 단다. 형식은 `기호: 의미 (단위)`이고, 무차원 값은 (무차원)으로 적는다. 해설은 기호 목록이 끝난 뒤 새 문단으로 쓴다.
- 표·그림·수식에 번호를 매기고, 본문에서 번호로 먼저 언급한 뒤 배치한다. 번호는 문서 전체에서 1부터 빠짐없이 이어진다. (type이 예외를 정할 수 있음)
- 표에는 단위를 적고, 열 이름에 기호만 쓰지 않고 이름을 붙인다 (예: "투과율 $T_i$").
- 그림 안의 수식도 본문과 같은 수식 표기로 쓴다. `w_i`, `C^` 같은 코드식 표기는 쓰지 않는다.

## 점검
- [ ] 장·절마다 설명 내용과 흐름을 적은 구성안을 사용자가 승인했고, 승인 전에 파일을 만들지 않음
- [ ] 서술은 "~다", 개조식은 명사형/"~함", 존댓말·대화체 없음
- [ ] 소제목이 모두 명사구
- [ ] 한글 발음 표기, 영어·한글 혼합 명사 없음
- [ ] 상투어, 메타 안내 절, 허용되지 않은 목차·부제목·요약 상자 없음
- [ ] 모든 숫자·인용·참고문헌이 확인된 것이고, 계산값과 미확인 값을 전달 메시지에 밝힘
- [ ] 정의 없이 처음 나오는 용어·기호 없음, 모든 수식 아래 기호 설명이 있고 빠진 기호 없음
- [ ] 표·그림 번호가 1부터 이어지고 본문에서 모두 언급됨 (type 예외 제외)
- [ ] 자리표시 문구와 예시 데이터가 남아 있지 않음
- [ ] 결과물을 렌더링해 직접 확인함
